# DEM 驱动的水文地理信息处理指南

> 本文可作为 `SKILL.md` 中的工作流章节，指导 Agent 从 DEM 构建适用于半分布式或分布式水文建模的河网、子流域、河段属性和拓扑数据。

## 适用范围

当用户希望从 DEM 完成以下一项或多项任务时使用本流程：

- DEM 水文校正；
- D8 流向与汇流累积计算；
- 河网提取、河段划分和河流分级；
- 子流域划分；
- 河段上下游拓扑分析；
- 子流域面积、河段长度和坡度计算；
- 根据雨量站空间位置计算各子流域的站点面积权重；
- 构建供水文模型读取的 HydroBase 表；
- 生成河网和拓扑质量检查成果。

如果用户仅要求制作坡度图、地形阴影图或等高线，不要触发完整水文处理链路。

## 目标成果

最低交付成果应包含：

1. 水文校正后的 DEM；
2. D8 流向栅格；
3. 汇流累积栅格；
4. 河网栅格；
5. 河段编号栅格；
6. Strahler 河流等级栅格；
7. 河网线矢量；
8. 子流域栅格；
9. 流域边界内的河段矢量；
10. `subbasins.csv`、`reaches.csv` 和 `topology.csv`；
11. 拓扑检查表、检查报告和检查图；
12. 用户提供雨量站点时，生成 `subbasin_rainfall_weights.csv`。

不要仅生成文件而不验证文件内容、坐标系、栅格对齐和拓扑关系。

## 默认技术路线

```text
输入 DEM + 流域边界
        ↓
输入检查与米制投影
        ↓
按流域边界外扩裁出分析 DEM
        ↓
Fill Depressions
        ↓
D8 Pointer
        ↓
D8 Flow Accumulation
        ↓
按汇水面积阈值提取河网
        ↓
Stream Link Identifier
        ↓
Strahler Stream Order
        ↓
Raster Streams to Vector
        ↓
Subbasins
        ↓
在完整分析范围建立河段拓扑
        ↓
按真实流域边界裁切
        ↓
面积、长度、坡度与上下游关系
        ↓
HydroBase CSV + 河段矢量 + 拓扑检查

若提供雨量站点：

        ↓

        ↓
各子流域雨量站面积权重
        ↓

```

## 核心约束

### 先建立完整拓扑，再按真实边界裁切

不要先把所有水文结果严格裁到真实流域边界，再推断上下游关系。严格裁边可能切断边界附近的河段，使正常河网被误判为多个出口。

推荐做法：

1. 将流域边界向外扩展一定距离；
2. 在外扩分析范围内完成 DEM 水文分析和河段拓扑；
3. 保留完整拓扑关系；
4. 最后按真实流域边界筛选河段和子流域；
5. 下游河段离开真实流域时，将其记为流域出口。

如果输入 DEM 已经严格裁到真实边界，外扩边界无法恢复缺失的边界外高程。此时应提示用户更换覆盖范围更大的 DEM，或明确说明多出口和边界河段可能不可靠。

### 面积、长度和坡度必须在米制投影下计算

不要直接使用经纬度坐标计算面积、河长或坡度。

- 如果 DEM 是地理坐标系，应投影到适合研究区的 UTM 或其他当地米制投影；
- 流域边界和其他矢量数据应重投影到 DEM 的分析坐标系；
- 不要猜测缺失的 CRS；缺少 CRS 时停止并请求用户确认；
- 垂向单位不是米时，应先进行单位换算或在结果中明确单位。

## 输入检查

开始处理前检查以下内容：

| 检查项 | 要求 | 不满足时的处理 |
|---|---|---|
| DEM 文件 | 可读取、单波段、具有有效 CRS | 停止并报告 |
| 流域边界 | 有效 Polygon/MultiPolygon，具有 CRS | 修复无效几何；CRS 缺失则停止 |
| 空间覆盖 | DEM 完整覆盖真实流域，最好覆盖外扩区 | 不完整时警告或请求更换 DEM |
| 水平单位 | 米制投影 | 自动投影或请求目标 CRS |
| 垂向单位 | 已知，原则上为 m | 换算或记录单位 |
| NoData | 明确且不会与真实高程混淆 | 设置独立 NoData 值 |
| 分辨率 | X/Y 分辨率合理且像元面积可计算 | 异常时停止 |
| 雨量站点（可选） | 有效点要素、具有 CRS 和唯一站点标识 | 清理无效记录；CRS 或标识缺失则停止权重计算 |
| 输出目录 | 独立于原始数据目录 | 不覆盖原始 DEM |

在报告中记录输入路径、CRS、分辨率、NoData、分析范围、河网阈值和软件版本。

## 处理步骤

### 1. 准备分析 DEM

1. 检查 DEM 和流域边界是否相交；
2. 将 DEM 转换到米制投影；
3. 将流域边界转换到同一 CRS；
4. 对流域边界进行外扩，建议把外扩距离作为可配置参数；
5. 按外扩边界裁出分析 DEM，以减少计算量；
6. 保留原始 DEM，不在原文件上修改。

外扩距离应根据 DEM 分辨率、流域尺度和出口附近地形确定。若用户没有指定，可提供一个保守默认值并在输出报告中记录，不要把默认值描述为普遍最优值。

### 2. 填洼

使用 WhiteboxTools：

```text
FillDepressions
```

作用是移除阻断 D8 排水路径的封闭洼地，并处理平坦区。

注意：

- 默认使用填洼，不同时叠加多种水文校正方法；
- `fix_flats=True` 时，应检查平坦区是否形成合理流向；
- 如果采用其他水文校正方法，应将其作为独立方案，并记录方法、参数及其对流向结果的影响；
- 不要在没有比较或说明的情况下叠加多种水文校正方法。

输出建议：`01_dem_filled.tif`。

### 3. D8 流向

使用：

```text
D8Pointer
```

必须在后续所有步骤中保持同一种指针编码。使用 Whitebox 默认编码时设置：

```text
esri_pntr=False
```

Whitebox 默认 D8 编码为：

```text
64  128   1
32    0   2
16    8   4
```

不要把 Whitebox 编码当作 ESRI D8 编码解析。编码不一致会直接造成错误的上下游关系。

输出建议：`02_d8_pointer.tif`。

### 4. 汇流累积

使用：

```text
D8FlowAccumulation
```

如果输入是上一步的 D8 Pointer，应明确设置：

```text
pntr=True
esri_pntr=False
out_type="cells"
```

输出使用上游汇入像元数量，便于将汇水面积阈值转换为像元阈值。

输出建议：`03_d8_flow_accumulation.tif`。

### 5. 按汇水面积提取河网

使用：

```text
ExtractStreams
```

不要把以平方千米表示的阈值直接传给 WhiteboxTools。先计算：

```text
cell_area_m2 = |a × e - b × d|
threshold_cells = ceil(stream_area_km2 × 1,000,000 / cell_area_m2)
```

其中 `a、b、d、e` 来自栅格仿射变换。对普通无旋转栅格，也可理解为 `|resolution_x × resolution_y|`。

河网阈值控制河网密度和子流域数量。Agent 应：

- 优先采用用户指定的起始汇水面积；
- 未指定时，根据流域尺度、DEM 分辨率和目标模型空间离散程度提出参数；
- 记录面积阈值和换算后的像元阈值；
- 不要为了得到“看起来好看”的河网反复调参而不记录过程。

输出建议：`04_streams.tif`。

### 6. 河段划分

使用：

```text
StreamLinkIdentifier
```

每个源头至汇流点、汇流点至下一汇流点或出口之间的河段应具有独立 `reach_id`。

输出建议：`05_stream_links.tif`。

### 7. 河流分级

使用：

```text
StrahlerStreamOrder
```

保持与 D8 Pointer 相同的编码设置。河流等级应作为河段属性写入 `reaches.csv` 和河段矢量。

输出建议：`06_strahler_order.tif`。

### 8. 河网矢量化

使用：

```text
RasterStreamsToVector
```

输入河网栅格和 D8 Pointer。完成后检查：

- 输出是否包含 CRS；
- 河流方向是否从上游指向下游；
- 线是否在汇流点正确连接；
- 是否存在零长度或孤立线段。

如果 WhiteboxTools 输出的 Shapefile 缺少 `.prj`，应从 D8 Pointer 或 DEM 写入正确 CRS，而不是猜测。

输出建议：`07_streams_vector.shp`。

### 9. 子流域划分

使用：

```text
Subbasins
```

输入 D8 Pointer 和河网栅格。检查每个河段是否能够映射到一个有效子流域。

输出建议：`08_subbasins.tif`。

## 河段拓扑分析

拓扑分析应基于 `D8 Pointer + Stream Links + Flow Accumulation`，并在真实边界裁切前完成。

### 河段到子流域映射

对每个 `reach_id`：

1. 读取该河段所有河道像元位置的 `subbasin_id`；
2. 排除 NoData 和非正值；
3. 采用出现次数最多的有效 `subbasin_id`；
4. 如果没有有效值，不要静默使用 `reach_id` 代替，应记录为缺失映射并触发检查警告。

### 确定河段最下游像元

对一个河段，候选最下游像元满足：

- D8 下游像元不再属于当前 `reach_id`；或
- D8 指针无效或流出栅格范围。

如果存在多个候选点，优先选择汇流累积值最大的候选点。多个互不一致的直接下游河段应被记录为拓扑异常。

### 确定下游河段

从河段最下游像元开始沿 D8 继续追踪：

1. 如果进入另一个正值 `reach_id`，该河段即为 `downstream_reach_id`；
2. 如果中间出现少量非河道像元，继续沿 D8 追踪，不要立即判定为出口；
3. 如果流出分析栅格，记为 `0`；
4. 如果重复访问同一像元，判定为 D8 循环并停止；
5. 设置最大追踪步数，超过限制时停止并记录异常。

### 构建上游关系

下游关系建立后，反向汇总所有指向当前河段的河段，得到：

```text
upstream_reach_ids
upstream_count
```

约定：

- `downstream_reach_id = 0` 表示离开目标流域；
- `upstream_count = 0` 表示源头河段；
- 不要使用空字符串或 NaN 表示出口，以免水文模型读取时产生歧义。

### 边界裁切后的拓扑

完整拓扑建立后，仅保留与真实流域相交的河段：

- 下游河段仍在保留集合中：保留原下游关系；
- 下游河段不在保留集合中：将当前河段设为边界出口，`downstream_reach_id = 0`；
- 上游关系必须根据裁切后的下游关系重新反向计算。

不要仅根据裁切后线段的空间接触关系重新猜测上下游。

## 水文属性计算

### 子流域面积

对真实流域边界内每个 `sub_id` 统计有效像元数：

```text
area_km2 = valid_cell_count × cell_area_m2 / 1,000,000
```

如果需要更精确的边界面积，应说明栅格像元中心法与矢量精确相交法的差异。用于栅格水文模型时，优先保持面积计算与模型栅格离散方式一致。

### 河段长度

沿 D8 栅格中心路径累计相邻河道像元之间的距离：

- 水平移动：使用 X 分辨率；
- 垂直移动：使用 Y 分辨率；
- 对角移动：使用两方向距离的平方和开方；
- 对存在旋转或错切的仿射变换，直接使用两个像元中心的投影坐标距离。

只统计真实流域内且上下游两端都有效的河网连接。输出单位为米。

### 河段坡度

推荐定义：

```text
slope_m_m = accumulated_nonnegative_elevation_drop / length_m
slope_percent = slope_m_m × 100
```

同时输出：

```text
elev_up_m
elev_down_m
drop_m
```

处理规则：

- 排除 DEM NoData；
- 长度为 0 时坡度设为缺失并触发警告；
- 水文校正 DEM 理论上应沿下游不升高；若出现大量负落差，应检查 D8 编码、DEM 与河网是否对齐；
- 不要在没有说明的情况下用绝对高差掩盖逆坡。

## 子流域雨量站面积权重

当用户提供雨量站点，并要求把站点降雨分配到各子流域时，采用像元级最近站分区计算面积权重。该方法等价于在子流域栅格分辨率下，用 Thiessen 分区统计每个站控制的子流域面积比例。

### 方法定义

对每个子流域有效像元：

1. 计算像元中心坐标；
2. 找到距离该中心最近的雨量站；
3. 将该像元唯一分配给该站；
4. 在每个子流域内统计各站获得的像元数；
5. 用像元数占比作为站点权重。

对子流域 `s` 和雨量站 `i`：

```text
weight(s, i) = count(s, i) / total_valid_cells(s)
```

其中 `count(s, i)` 是子流域 `s` 内分配给站点 `i` 的像元数。对于等面积投影栅格，像元数比例等于面积比例。

这是最近邻面积分区，不是距离反比插值。不要把结果描述为 IDW 权重。

### 输入要求

需要：

- 子流域编号栅格；
- 雨量站点矢量；
- 雨量站唯一标识字段，例如 `station` 或 `station_id`。

计算前必须检查：

1. 子流域栅格具有 CRS、仿射变换和明确 NoData；
2. 有效子流域编号为正整数；
3. 雨量站图层具有 CRS；
4. 所有有效几何均为 `Point`；
5. 站点标识非空且唯一；
6. 至少存在一个有效雨量站；
7. 站点已经转换到子流域栅格 CRS；
8. 计算距离所用 CRS 为合适的米制投影。

如果多个站点具有完全相同的坐标，最近邻查询的并列结果可能不稳定。Agent 应要求用户确认合并规则、保留规则或站点优先级，不要任意分配。

不要仅因为站点位于总流域边界之外就自动删除。边界附近的外部站点可能控制流域内一部分 Thiessen 区域。候选站点集合应由用户提供的数据范围或明确的站点筛选规则决定。

### 计算步骤

#### 1. 读取有效子流域像元

建立有效掩膜：

```text
valid = subbasin_id > 0
valid = valid AND subbasin_id != nodata
```

提取所有有效像元的行列号，并通过栅格仿射变换取得像元中心坐标。

#### 2. 建立站点空间索引

将所有有效站点的 X/Y 坐标建立最近邻空间索引。Python 实现可使用：

```text
scipy.spatial.cKDTree
```

对所有有效像元中心执行最近邻查询，得到每个像元对应的站点索引。

当有效像元数量很大时，不应一次生成全部坐标导致内存压力。应按栅格窗口或像元块分批查询，并累计 `subbasin_id × station_id` 计数。分块和一次性计算应产生相同权重。

#### 3. 按子流域统计权重

对每个 `subbasin_id`：

1. 选择属于该子流域的有效像元；
2. 统计每个站点被分配的像元数；
3. 用各站像元数除以该子流域有效像元总数；
4. 仅输出权重大于 0 的站点记录；
5. 按 `subbasin_id`、`station` 稳定排序。

不得用站点到子流域质心的最近距离替代像元级面积统计。质心最近站只能得到单站分配，不能表达一个子流域横跨多个站点控制区的情况。

### 输出格式

主输出采用 long format：

#### `subbasin_rainfall_weights.csv`

| 字段 | 含义 |
|---|---|
| `subbasin_id` | 子流域编号 |
| `station` | 唯一雨量站标识 |
| `weight` | 站点在该子流域中的面积权重 |

示例：

```csv
subbasin_id,station,weight
1,S01,0.625
1,S02,0.375
2,S02,1.000
```

如果 HydroBase 其余表使用 `sub_id`，可以将 `subbasin_id` 统一改为 `sub_id`，但同一项目内必须保持一致并记录字段映射。

可同时生成宽表用于人工检查：行表示子流域，列表示雨量站，单元格为权重。宽表主要用于检查，不应替代 long format 主输出。

### 权重质量检查

对每个子流域检查：

```text
abs(sum(weight) - 1.0) <= tolerance
```

建议同时检查：

- 所有权重有限且满足 `0 < weight <= 1`；
- 每个有效子流域至少有一个站点记录；
- 输出中的子流域集合与目标子流域栅格一致；
- 输出中的站点标识全部存在于站点图层；
- 不存在重复的 `subbasin_id + station` 组合；
- 站点像元计数总和等于对应子流域有效像元数；
- 宽表每行之和为 1；
- 随机抽查若干边界像元，其最近站分配符合空间位置。

浮点误差范围应显式设置，例如 `1e-6`，不要要求二进制浮点结果严格等于 1。

建议生成检查图，显示子流域边界、雨量站位置、像元最近站分区及站点编号，以发现 CRS 错误、遗漏站点或异常控制区。

### 与降雨时间序列结合

权重表仅表示固定站网下的空间面积比例。对子流域 `s`，时刻 `t` 的面雨量可计算为：

```text
P_subbasin(s, t) = sum(weight(s, i) * P_station(i, t))
```

如果某时刻部分站点缺测，不要把缺测值静默当作 0。应根据项目规则选择：

- 将该时刻子流域降雨标记为缺失；或
- 仅在允许的情况下，对可用站点权重重新归一化；或
- 先完成站点时间序列缺测插补，再应用固定权重。

采用哪一种策略必须记录。若站网随时间变化，固定权重不能直接代表所有时期，应按有效站网分时段重新计算权重或采用明确的动态处理规则。

## HydroBase 输出规范

### `subbasins.csv`

建议字段：

| 字段 | 含义 |
|---|---|
| `sub_id` | 子流域唯一编号 |
| `area_km2` | 真实边界内子流域面积 |
| `cell_count` | 有效像元数量 |
| `reach_count` | 子流域包含的河段数 |
| `reach_ids` | 子流域内河段编号列表 |
| `outlet_reach_ids` | 离开该子流域的河段编号 |

### `reaches.csv`

建议字段：

| 字段 | 含义 |
|---|---|
| `reach_id` | 河段唯一编号 |
| `sub_id` | 对应子流域编号 |
| `strahler_order` | Strahler 河流等级 |
| `length_m` | 河段长度 |
| `elev_up_m` | 上游端高程 |
| `elev_down_m` | 下游端高程 |
| `drop_m` | 累计非负高程降 |
| `slope_m_m` | 河段坡度 |
| `slope_percent` | 百分比坡度 |
| `upstream_count` | 直接上游河段数 |
| `upstream_reach_ids` | 直接上游河段列表 |
| `downstream_reach_id` | 直接下游河段，出口为 0 |
| `downstream_sub_id` | 下游子流域，出口为 0 |
| `is_headwater` | 是否为源头河段 |
| `is_outlet` | 是否为流域出口 |

### `topology.csv`

建议字段：

| 字段 | 含义 |
|---|---|
| `sub_id` | 当前子流域 |
| `reach_id` | 当前河段 |
| `upstream_count` | 直接上游河段数 |
| `upstream_reach_ids` | 直接上游河段列表 |
| `downstream_sub_id` | 直接下游子流域 |
| `downstream_reach_id` | 直接下游河段 |
| `topo_level` | 从源头向下游的拓扑层级 |
| `is_headwater` | 源头标记 |
| `is_outlet` | 出口标记 |

CSV 使用 UTF-8 编码。编号字段应保持整数，出口使用 `0`，列表字段使用稳定且已记录的分隔符。

同时建议输出带相同属性的 `reaches_clipped.gpkg`，便于在 ArcGIS Pro 或 QGIS 中核查。

### `subbasin_rainfall_weights.csv`（提供雨量站时）

采用 long format 保存子流域—雨量站组合及面积权重。每个子流域的权重和必须在设定容差内等于 1。站点字段必须使用唯一标识，不要使用可能重复的展示名称作为连接键。

## 必须执行的质量检查

### 栅格一致性

确认 DEM、D8 Pointer、Flow Accumulation、Streams、Stream Links、Stream Order 和 Subbasins：

- 行列数一致；
- CRS 一致；
- 仿射变换一致；
- 像元网格完全对齐。

任一项不一致时停止，不要通过数组索引强行组合。

### 拓扑检查

至少检查：

1. 是否存在自循环：`reach_id == downstream_reach_id`；
2. 是否存在两个或多个直接下游候选；
3. 是否存在完整河段循环；
4. 所有非零下游编号是否真实存在；
5. 每个保留河段是否具有有效子流域；
6. 是否存在零长度河段；
7. 拓扑排序是否能处理全部河段；
8. 出口数量是否符合研究区预期。

单出口流域通常应有一个总出口，但多个出口不应被自动改成一个。多个出口可能来自：

- DEM 被真实边界严格截断；
- DEM 覆盖不完整；
- 河网在边界处被切断；
- 阈值导致河网不连续；
- D8 指针编码错误；
- 平坦区或残留洼地处理异常；
- 研究区本身确有多个独立排水系统。

Agent 应先诊断原因，再决定是否调整输入或参数。

### 数值检查

检查：

- `area_km2 > 0`；
- 正常河段 `length_m > 0`；
- 坡度没有无穷值；
- 子流域面积总和与栅格化流域面积基本一致；
- 河段数量与 Stream Links 中的有效编号数量一致；
- 河流等级为正整数；
- 高程和长度单位与字段名称一致。

### 雨量站权重检查

提供雨量站时，还要检查：

- 雨量站和子流域栅格使用相同的米制 CRS；
- 站点标识唯一且不存在空值；
- 每个有效子流域均有权重记录；
- 每个子流域的权重和在容差内等于 1；
- 不存在负权重、非有限权重或重复组合；
- 权重计算方法和缺测处理规则已记录。

### 拓扑检查图

检查图至少显示：

- 真实流域边界；
- 子流域分区；
- 河段线；
- 河段流向箭头；
- `reach_id`；
- Strahler 等级；
- 出口位置；
- 河段数、子流域数、出口数和异常数。

河段过多时可以仅标注高等级河段、出口和抽样河段，但不能省略出口与流向表达。

## 异常处理顺序

### 没有提取到河网

依次检查：

1. 汇流累积是否有效；
2. 面积阈值是否大于整个流域面积；
3. 平方千米到像元数的换算是否正确；
4. DEM 是否使用米制投影；
5. NoData 是否污染了分析区。

不要直接把阈值设为极小值后继续。

### 出现多个出口

依次检查：

1. 输入 DEM 是否严格裁边；
2. DEM 是否完整覆盖外扩分析区；
3. 完整拓扑是否在裁切前建立；
4. 河网是否连续；
5. Pointer 编码是否一致；
6. 是否存在真实的多排水系统。

不要通过删除其他出口强制制造唯一出口。

### 出现循环或异常分叉

停止 HydroBase 最终交付并保留诊断文件。检查 D8 指针、栅格对齐、NoData、平坦区和河段编号；不要静默选择其中一个下游分支作为最终结果。

### 子流域与河段无法对应

检查 Subbasins 是否与 Stream Links 使用同一 D8 Pointer 和同一河网栅格生成。不要默认令 `sub_id = reach_id`，除非目标模型明确规定两者必须同号且已经验证其成立。

## Agent 执行规则

1. 先检查输入，再运行耗时工具；
2. 优先从数据推导参数，不把示例值当作固定标准；
3. 保留原始文件，所有结果写入独立输出目录；
4. 不未经授权删除或覆盖用户已有成果；
5. 每一步验证输出文件存在且可读取；
6. 保存参数、路径、CRS、分辨率、阈值和异常信息；
7. 只有在栅格一致性和拓扑检查完成后，才声明 HydroBase 构建成功；
8. 如果运行环境缺少 WhiteboxTools、Rasterio、GeoPandas、SciPy 或其他所需依赖，明确列出缺失项；
9. 无法获得必要 CRS、DEM 覆盖或流域边界时停止，不猜测关键空间信息；
10. 如果用户只要求方案或代码审查，不自动运行数据处理或覆盖外部文件。

## 完成条件

只有同时满足以下条件，才将任务标记为完成：

- 标准河网提取和子流域划分结果全部生成；
- 所有核心栅格具有一致网格和 CRS；
- 每条有效河段具有明确的子流域和上下游关系；
- 面积、长度和坡度使用正确单位；
- 没有未解释的自循环、拓扑循环或异常分叉；
- 出口数量已经验证或解释；
- HydroBase 表、河段矢量、检查报告和检查图均已生成；
- 提供雨量站时，子流域雨量站权重表已生成，并通过逐子流域权重和检查；
- 最终答复说明使用的关键参数、发现的异常及其影响。
